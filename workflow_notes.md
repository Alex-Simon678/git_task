# Trunk-Based Development

All developers merge their code (changes) into a single branch (named "trunk"/"main" mostly). It requires frequent merging. I would use this in fast-paced enviroments. It reduces merge-conflicts and ensures that the dev team is always working on an up to date version.

# GitFlow
Assings different roles to different branches. There is a main/master branch that is production ready code, and the develop branch that contains the code waiting for the next release. It is ideal when a software has scheduled release cycles.

# GitHub Flow
All changes have feature branches and they are merged in a main branch with pull requests. It requires constant code review and discussions. I would use this for applications that has code deployed frequently.
